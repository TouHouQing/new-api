# 以影策为主的 AI 视频创作平台整合规格

## 授权与基线

用户已批准上一轮整合方案，并要求“务必以影策为主”。本次继续自主开发、测试与本地试用；不需要再次批准该方案。原项目工作区及历史媒体保留。

- 主工程：`ddcat-ai/open-ai-canvas`，固定提交 `9fdebd07841b71caf4fa5e116b8a3b8af3a959ea`。
- 迁入来源：同级 `new-api` 的实际工作区，包含其未提交制作能力；提交基线不是完整迁入来源。
- 图片补充：`HuFakai/infinite-canvas`，固定提交 `aadd02f42c575bdadb93470391e968b406fc26ad`，逐工具择优。
- 主体归属：影策前端、后端、用户、项目、资源、任务、存储与费用体系；New API 仅作为可选模型渠道和旧工程迁移来源。
- 本地生产验收；允许调用用户已部署的本地模型；不调用外部付费模型，不向外部平台发布作品或发送消息。
- 不覆盖现有生产数据或源代码，不自动提交或推送，不重复下载模型权重，不清理用户媒体和非本任务缓存。

## 产品与数据规则

1. 默认创作路径为：作品类型与需求、镜头草案、画面制作、剪辑与声音、检查与导出。高级画布与专业参数按需进入。
2. 画布、分镜、时间线、审片和 Agent 使用同一项目与同一业务动作。
3. 每种实体只有一套权威数据。复用并扩展影策 `AssetVersion`、`ShotRevision`、`ShotArtifact` 与任务结构。
4. 时间线片段固定具体候选和资源；生成新候选或修改下一版提示词不改变已完成剪辑。
5. 精准返工绑定某个片段使用实例、源时间、节目时间和区域，保留无关音轨、字幕、历史版本与源文件。
6. 所有生成遵循统一模型能力、参考素材校验、预算、执行记录和幂等合同。用户无需临时生成个人 API Key。
7. 不确定的上游提交先核对已有回执；任务成功、文件可读与作品质量合格分别记录。
8. 迁移必须覆盖当前与历史版本、所有辅助媒体、角色参考、GLB、声音、字幕、审片、剧集与区域版本；无法解释的旧字段必须显式报告。
9. 原工程、源媒体及旧任务不由新 worker 自动重新生成。身份与 ID 显式映射，敏感配置和浏览器会话不进入工程包。
10. 网页 Agent、MCP、Skills 调用相同权限与制作动作；浏览器桥只用于必须依赖活动视口的操作。
11. 主平台可直接使用服务端本地模型适配器；云渠道与可选 New API 网关由管理员配置，用户费用统一结算。
12. 移入 AGPL 代码时保留许可证和作者声明，并记录来源；依赖的独立许可继续适用。

## 验收合同

- 每个领域必须有来源、目标实现、入口、数据迁移规则、真实测试和剩余限制，不以菜单或接口存在计通过。
- 旧平台原有 40 项验收逐项映射到本平台；原来的失败与未验证项不改成通过。
- 至少完成一条真实本地制作链路：创建项目、编辑分镜、实际生成、选择候选、剪辑声音字幕、审片、导出、重开与恢复。
- 已迁入的候选与媒体以文件 SHA、具体版本引用和导出探测验证。未迁移项必须阻止“全部完成”结论。
- 必测异常：丢失提交响应、断网与重开、租约过期、重复请求、非法图片、越权、删除保护、取消晚到结果、辅助媒体遗漏、变速/重复片段/区域版、磁盘不足。
- 本地模型实际质量单独审核；角色连续性、商品几何、局部移除等失败记录保留。外部授权发布、原生音画模型等外部条件不伪造。
- 测试、类型检查、构建和真实页面试用针对实际产品。静态 HTML、假成功和测试替身不作为真实模型或生产验收。

## 完成措辞

本规格全部条目有对应实现且通过规定验收前，只报告已经完成的具体范围及剩余工作，不宣称整个平台已完成或无 bug。
