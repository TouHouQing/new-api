# 创作目标与分镜方案

实现使用影策项目、镜头、素材和任务作为唯一制作数据。Schema 70 的基础目标、方案历史、未知响应恢复与独立备份恢复已通过本地生产验收；新增的 v8 旧工程制作方案转换仍待同一发布版本的界面与恢复验收。接口存在不表示模型质量已通过。

## 创作路径

在项目设置中填写作品类型、核心信息、观众、成片目标时长、语言、语气及约束。章节拆分与镜头制作沿用这份目标。目标时长指整部作品，不代替模型支持的单镜头时长。项目设置使用读取时的revision；其他页面改动同一设置时保留本页输入，进度或主图更新不会清空草稿。

在镜头的“镜头意图与接戏”中填写镜头作用、观众需要理解的信息、情绪、画面重点和前后镜延续。衣着、表情与道具状态绑定明确素材版本，随不可变的ShotRevision保存。专用`PATCH .../shots/:shotId/intentions`动作保留其他脚本、机位、动作节拍和提示词；省略的意图或状态继承原版本，空对象或空数组表示明确清除。

“适用阶段”可选择同时采用、只用于图片或只用于视频。图片与视频固定不同参考时，各自沿用对应版本与图片。每项状态可从项目素材库选择最多12张固定参考图，也可查看、移除原图。服务端、MCP、提示词与实际请求使用相同阶段范围；全体原设定仍保存在任务审计快照中。

服务端生成入口核对项目权限、活动镜头及shotRevisionId，固定productionContext并采用创作要求。额外接戏图片参加原生参考校验及模型能力限制。不能用客户端同名快照冒充服务器确认；模型不支持足够参考图时应选择合适模型或先制作关键帧。传入参考不保证角色外观或商品几何已经一致。

项目简介也固定进实际生成要求，后续编辑不改变旧任务输入。创作说明、镜头意图与接戏要求总计超过64KiB时先返回明确错误，请精简后再提交。

## 旧工程制作方案

从 v8 起，首次导入会把原目标、观众、时长、制作说明、镜头意图和接戏状态写入原生项目及脚本版本，并保存方案快照。没有文本节点的镜头沿用原有文本、图片或视频提示中的描述。

已经导入的工程通过“剪辑版本 → 预览旧工程转换”检查升级。尚未转换制作方案时，确认后新增独立剪辑及“原工程制作方案”章节，原有镜头、目标、人工修改、文件和导入回执继续保留。新章节支持原生编辑和方案历史；目标从历史预览进入项目设置后先读入草稿，再核对保存。v9 声音转换沿用已存在的 v8 方案，不再创建相同章节或恢复用户已经改动的内容。响应未知时查询或重放原转换，不重新生成媒体。

原平台未指定版本时使用当时保存的素材定义；指定版本或连线 Take 则固定其原始说明、图片与外观，不替换为素材最新状态。升级需要额外保留原定义时只新增明确版本，保留当前素材主版本。参考图片、视频各自不同的状态带有对应`stage`。仍未迁入编辑能力的高级设定继续显示为存档内容。

## 导演预演迁移

v10 将原工程的导演台转换为影策原生预演场景，并在原画布追加入口。演员、道具、GLB 原单位与固定素材版本、对象轨道、相机环绕轨道、跟随和看向对象继续编辑；跟随位置和注视目标分别计算，关键帧以偏移保存。预演支持方形及横竖画幅，`point` 对应“指向前方”。模型加载后沿用原动作选择，缺失的对象、资源或固定版本会阻止转换。

预览令牌绑定画布版本及转换前后摘要。确认与独立剪辑回执在同一事务保存，并保留转换前画布历史和资源引用；并发编辑后必须重新预览。已转换场景及后来删除的内容不会被原工程重建。旧版转换令牌仍对应原来的固定回执。当前工作剪辑继续保留。

预演台的“3D 文件”可导出包含动画与机位的 GLB，导出后保存历史并下载；原工程的历史 GLB 也在同一入口下载。导出使用已加载模型，拒绝把加载失败的占位人物作为原模型交付。GLB 的原生场景说明保留在 extras 中，编辑器网格、选中框、骨骼控制器不进入文件。材质和环境在不同 GLB 查看器中的表现需实际核对；完整可编辑项目仍通过项目数据和备份恢复。

白膜视频按选定镜头的摄影机、画幅和帧率逐帧渲染，不录制编辑窗口。构图回写也使用镜头机位；白膜封面对应第一帧。渲染显示进度，保存前可以取消，取消后保留原有内容并释放临时渲染器和编码 Worker。长镜头分批编码并清理中间帧；时长需要对齐实际帧边界。

## 方案历史与恢复

章节页的“方案历史”保存重新拆分、移除镜头和恢复操作前的完整方案，包括镜头、脚本版本、固定素材引用、选定候选与状态。移除只从当前方案隐藏镜头，保留旧任务、版本、原文件和已保存剪辑的具体引用。整个项目或章节的明确删除仍是独立删除动作。

生成新分镜前保存`shot-plan-source`的摘要和镜头列表。生成期间来源发生变化时，保留草稿并重新确认采用，避免再次调用模型。草稿固定生成时的素材版本与名称；没有来源快照的旧任务先进入待采用草稿，不猜测其历史参考版本。

历史预览包含完整snapshot和每页20条脚本。恢复需要分别携带历史record.payloadSha256、当前source.sha256和当前镜头列表。服务器先保留当前方案，再恢复原镜头、参考和选定候选，不新建媒体。章节正文、创作目标和剪辑继续保持各自版本；差异通过warnings提示，恢复后需要人工核对。

预览可展开镜头意图、提示词、阶段与原参考图，并单独核对方案保存时的目标及简介。历史缺图时不会拿当前角色图片代替；需要恢复对应原文件或明确选择其他版本。

替换和恢复使用稳定requestId与完整请求摘要，按项目事务提交。响应未知时重放同一请求；`replayed=true,current=false`表示原操作已完成且之后有新修改，本次没有重新覆盖。历史任务晚到的产物保留在原镜头及素材库，不选入新方案或推进新工作流。

## 普通生成请求去重

普通`POST /api/tasks`可以通过`input.metadata.clientOperationId`固定生成意图。相同账号、编号和原始请求复用一条任务及一笔原生费用预占；同编号变更内容返回409和`task_intent_changed`。恢复查询不依赖当前模型是否仍在目录中。

`GET /api/tasks/by-client-operation/:operationId`只返回当前账号已被服务器接受的任务。未知网络响应先核对原任务；404仅表示尚未找到，不能作为可以重复付费提交的证明。章节页会保存待核对请求并提供原任务恢复入口。服务端明确拒绝且未创建任务时，解除本地待核对状态。

## 数据与边界

Schema 70增加`projects.creative_brief_json`、`shot_revisions.narrative_json/reference_states_json`、`shots.archived`以及任务的操作编号和原始意图摘要。唯一新增表`project_shot_plan_records`保存不可变历史与原生操作回执。文档正文沿用结构化存储配额；固定引用参加资源删除保护。

SQLite与PostgreSQL使用同一模型和事务合同。只读迁入低于70的库时，新字段保持空值、镜头保持可见，不虚构历史目标或重新启动任务；声称70却缺列或缺表时拒绝。迁入记录、回执、历史媒体以及设置密钥必须随完整备份保留。

MCP的目标、镜头意图、方案读取、替换、恢复和原任务查询调用同一API。写操作需要明确确认和原版本；Skills描述同样的操作与恢复规则。接口、任务成功、文件可读和作品质量分别验收。
