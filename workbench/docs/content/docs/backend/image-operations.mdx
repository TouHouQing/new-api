# 本地图片处理

图片处理沿用影策用户、任务队列、资源、素材版本、容量配额与保存恢复能力，不调用模型、不创建用户 API Key、不产生模型账单。图片节点的裁剪、非均匀切图和插值缩放提交后台任务；关闭页面不会取消任务。任务中心可查看结果并添加回原画布；源节点被删除或换图时，保留素材结果并拒绝覆盖当前内容。

## API

### AI选区修改与表情合成

AI编辑使用原有 `POST /api/tasks` 或画布原子批次接口，在 `input.metadata.nativeImageEdit` 绑定 `version=1`、`sourceNodeId`、`resourceId`、`expectedSourceSha256` 及二选一的 `mask` / `emotion`。`mask` 使用原图实际宽高、`mode=keep` 和涂抹笔画；`emotion` 使用整数像素 `region={x,y,width,height}` 及原图坐标 `faceBox={x,y,width,height}`。入队前核对本人原图节点、文件摘要和非空合法区域，再保存服务端计算的源快照；未知参数、两类区域同时提交、空选区及外部资源都会拒绝。

模型任务只生成候选。选区修改将完整候选按原图比例整理后，仅替换涂抹区域；表情任务将人脸裁切候选按裁切比例整理，并仅在目标椭圆内羽化及校正边缘色差。比例差超过1%时保留原任务结果并报告失败，不任意拉伸。未修改像素、透明度和原图ICC保持；原图文件不覆盖。每张成功输出带 `nativeImageEdit={kind,sourceResourceId,sourceSha256,recipeSha256}` 回执，输出已经是完整画幅，客户端不得再次合成。

合成在通用下载与保存检查点执行，声明式模型和任务恢复使用同一路径。暂存文件过期后，重新下载原上游回执并重新合成，不重复推理。派生素材版本记录原资源、源SHA和处理配方。原生目标草稿及稳定操作编号保留关页恢复；成功保存候选不代表表情或角色相似度通过。

普通生成图片、视频及各音轨也在完成事务中登记固定 `AssetVersion` 与原任务 `AssetRepresentation`，结果返回 `assetId/assetVersionId`，画布引用该输出版本。后来的素材版本不改变该绑定。新媒体回填先清除旧版本引用，批次封面继承具体候选的版本。已成功但早期未登记版本的任务，可明确调用原 `POST /api/tasks/:id/recover-media` 核对检查点并补齐绑定；不重新生成、不下载、不改变执行次数或账单，也不覆盖用户改名、移动、已换素材及已指定版本。重复核对不再修改画布版本。

画布 Agent 的 `generate_media.imageEdit={sourceNodeId,useSavedMask:true}` 可采用该原图已保存的选区；`mode=image`，`referenceNodeIds` 仅含该原图。不推测涂抹位置。仍通过原生报价和界面审批；审批绑定选区内容，改选区后不能沿用旧批准。当前图像模型只支持一张参考图时，批注编辑仅提交批注后的参考，表情修改仅提交头部裁切；不会虚构第二张参考图或上游蒙版支持。

### 独立图层素材

透明前景的“另存独立素材”正在改为原生批处理。`GET /api/images/:resourceId/alpha-bounds` 只读扫描实际文件，返回源SHA、整数像素边界及empty/trimNeeded；包含16位alpha=1的边缘。`crop`配方可使用`cropPixels={x,y,width,height}`，与归一化`crop`二选一；可提供`expectedSourceSha256`拒绝将旧坐标用于新文件。

`POST /api/canvas-projects/:id/image-layer-groups/:nodeId/materials` 接收稳定requestId及刚读取的sourceGroupSha256。来源必须已原生合成且ready；仅处理明确transparent的前景。每层依据各自原文件和ICC裁去外部透明留白，共用一个`trim-layers`多输出任务；无需裁剪的复用原文件，空层在emptyLayerIds中列出，全部为空时拒绝。全为无需裁剪时直接复用，不建伪任务或重复媒体文件。普通手动组图已有独立原图，不再显示重复另存入口。

任务、来源标记与画布回执原子保存；完成后经原生历史一次添加独立素材节点，原图层保留。关闭页面不取消后台批处理，启动后继续恢复待回写任务。新来源或后续编辑不会被旧结果覆盖；重放历史采用回执不会恢复用户已撤销的节点。MCP同一入口为`yingce_save_image_layer_materials`，透明边界只读入口为`yingce_image_alpha_bounds`。本批主环境与隔离实例通过22项真实功能检查、6项稳定布局检查和3394个像素的原样核对；独立恢复保留此前26–46阶段断言，验证重启回写与原生撤销后旧回执不复活。证据为整合运行目录`phase47-native-materials-checkpoint.json`。首次AI拆层、区域提取、规格整理和背景修补等其余流程仍继续整合，不能把本批通过当作整个图片领域或整套合并完成。

遮罩提取与擦除正在接入本轮本地验收。画布的“局部重绘”中选择“提取区域”或“擦除区域”，按原图像素坐标另存透明PNG，不生成背景。通过“保存遮罩草稿”将笔画、原资源编号、尺寸和用途存入原生画布；只有服务端读回一致才显示保存完成。换图或尺寸不符时拒绝套用旧草稿。

对应 `recipe.operation=mask`，`mask` 包含 `width`、`height`、`mode=keep|remove` 和有序 `strokes`。每笔包含像素直径 `diameter`、是否擦除既有选区的 `erase`、二维像素坐标数组 `points`。最多256笔、合计8192点，并检查计算量上限；请求正文最多256KiB。任务和派生素材保存实际源SHA及完整配方，RGB样本、16位精度和RGB/灰度ICC保持，只有透明度变化。重试、检查点与采用沿用原生图片操作合同。完成开发不代表实际网页和恢复验收已经通过。

`POST /api/images/operations` 使用登录态，接收以下内容，返回普通任务：

```json
{
  "requestId": "client-operation-unique-id",
  "projectId": "owned-canvas-id",
  "sourceNodeId": "image-node-id",
  "resourceId": "owned-original-resource-id",
  "recipe": {
    "operation": "split",
    "split": {
      "rows": 2,
      "columns": 3,
      "horizontalLines": [0.37],
      "verticalLines": [0.23, 0.71]
    }
  }
}
```

`requestId` 长度为16到128字符。同一用户、同一编号及参数重复提交返回同一任务；编号对应不同参数返回409和 `image_operation_conflict`。网页按画布、源节点、资源和配方生成稳定编号，跨窗口和重开不会重复创建。外部调用方应保存自己的编号；编号是操作幂等标识。

可用配方互斥：

- `split`：`rows,columns` 为1到12整数，至少两张。可选横竖分割线按0到1表示，数量分别为行数减一、列数减一。均分向下取整，自定义分割线就近取整为原像素边界；不得交叉、重合或产生零像素图片。
- `crop`：`crop:{x,y,width,height}` 是相对于按EXIF正确朝向后的原图的归一化区域；越界拒绝，像素边界向外取整。
- `resize`：`resize:{targetLongEdge,algorithm}`，长边1到4096像素，保持比例；算法为 `nearest`、`bilinear` 或 `high`。这是CPU插值，不声称补出真实细节或AI超分。

仅接受当前用户已就绪的静态 PNG/JPEG/WebP，源文件不超过32MB且不超过16777216像素。检查真实文件头和内容，不信任客户端尺寸；支持EXIF八种朝向。动画不静默取首帧；不支持格式须先转换。输出为PNG，原文件不改写。

原生裁切、切图、最近邻缩放保留PNG的8/16位样本和非预乘透明像素；灰度透明图保持PNG灰度色彩类型。双线性及高质量插值保留16位输出，但插值本身会改变样本，不声明逐像素相同。PNG的ICC、gAMA、cHRM、sRGB及受支持HDR色彩描述保持原内容；JPEG分段ICC和WebP ICC登记到派生PNG，配置必须与RGB/灰度像素匹配。无配置不自动假设配置；CMYK、不匹配、损坏、重复或超限的配置明确拒绝，不静默去掉。ICC解压限制4MB；处理并发按保守峰值估算受1536MB进程内额度控制，等待可取消，不改变原生队列、任务输入快照或源SHA合同。此能力不等于所有色彩空间转换或AI超分；生产页面验收以最新检查点为准。

通过原有 `GET /api/tasks/:id` 读取状态与结果。成功结果含 `images[]` 的资源ID、素材ID、具体版本ID、实际尺寸、像素区域，以及 `imageOperation` 的源SHA256和配方快照。使用原有取消、重试和 `recover-media` 接口；失败保存不会转成新的模型推理。用户明确继续已取消的CPU配方时沿用原任务并复用已保存文件；模型任务仍执行原保存恢复与费用边界。

## 持久数据

### 识图规划与确认制作

图片拆层先运行普通 `canvas_text` 任务，再由用户核对2至8层，确认后提交原生 `image-layer-workflows`。识图本身不新建图片节点，也不自动开始图片生成。网页区分“提取素材，保留原图”和“分离前景，修补背景”；逐层核对名称、原像素提取范围及形状、是否重绘及独立制作要求。原像素提取无需配置图片模型。

识图任务通过 `POST /api/tasks`，`operation=text`，`input.mode=text`，`input.metadata.nativeLayerPlanning` 包含 `version=1,sourceNodeId,resourceId,expectedSourceSha256,instructions,purpose=materials|recompose,input=preview|original,maxCredits`。使用一个支持图片参考的文本模型，沿用渠道、队列、幂等编号、权限和原生计费；不创建用户API Key。识图与图片生成分别授权预算，0只允许免费模型，超出报价在创建任务和预占前拒绝。

服务端绑定本人原图，按真实朝向生成最长边1000像素的识图预览；`original` 保留原尺寸。任务保存原文件SHA、实际识图尺寸与预览SHA，不信任客户端预览。工作副本注入图片数据，持久输入不保存Base64大对象。模型回复与规范化规划在同一完成边界保存。`result.imageLayerPlanning.status=ready` 才有可用 `plan`；`needs_correction` 保留原回复和原因，文本请求成功不表示拆层规划或视觉质量合格。边界不确定的完整照片须人工框选，不自动转为付费重画。

本地 `yingce-local-text` 的新识图任务固定 `responseSchema=image-layer-plan-v1`，通过 Ollama 的 `format` 传递有限JSON Schema，明确必填图层参数、2至8层、实际参考尺寸及0至1000坐标，并关闭思考输出、降低采样随机性。格式约束仍需结合原图和业务规则校验，不保证主体识别或边界正确；不能查看图片时允许 `canPlan=false`。原任务未保存此约束版本时不自动添加，未使用格式的请求也不改变既有传输回执指纹。Agent取得不可用规划时明确返回需要修正，不显示为可执行图层计划，也不自动重新识图或生成图片。原理见 [Ollama 官方结构化输出说明](https://docs.ollama.com/capabilities/structured-outputs)。

`GET /api/canvas-projects/:id/image-layer-plans?sourceNodeId=…&resourceId=…&limit=20&cursor=…` 按当前原图分页读取规划和待完成任务。关闭窗口只停止页面等待，后台记录保留；重新打开先读取已有规划，待完成时不重复提交。已确认规划必须仍匹配原节点、原资源、原文件SHA和尺寸。换图后不能沿用旧范围。已有原像素提取、生成、去背景、合成与素材另存继续共用原生任务和固定素材版本。

Web Agent 的 `image_layer_plan` 使用当前支持识图的文本模型，始终展示识图预算与原图审批，批准后才提交一个原生文本任务；生成次数和费用计入同一运行上限，不新建图片草稿。后续拆层仍需单独核对图层及批准图片制作。MCP 对应 `yingce_plan_image_layers`（明确 `confirmPlanning=true`、稳定幂等编号及预算）和只读 `yingce_image_layer_plans`。这些入口正在本地合并验收，尚不能据此声明整个图片领域或整套合并完成。

本功能由Schema62引入，不新增第二套队列或素材表。`tasks.type=image_operation`、`provider=local`、`model=image-raster-v1`。原生队列使用租约及完成CAS；加密的 `media_recovery_json` 保存每个输出的检查点。上传键按任务及输出序号固定，暂存文件过期时可按原SHA验证后的源文件重建。

### 原生图层组合（Schema69，专项验收通过）

选择已有图片后可创建免费图层组，源图片保留。从底到顶叠放，支持可见性、透明度、原图像素位置及独立画面尺寸；拖动工作区节点不改变合成位置。建组与首个原生CPU任务、配额、回执同时提交。图片解码后按源配置转换到sRGB并以16位PNG输出；合成改变颜色空间及像素，不能声称派生结果与源ICC或样本原样相同。

`GET /api/canvas-projects/:id/image-layer-groups/:nodeId/source` 返回实际来源SHA、完整配方、snapshotSha256和ready。ready核对具体原生任务、当前布局、嵌套图层与固定输出，未完成预览不能加入制作。`POST /api/canvas-projects/:id/image-layer-groups` 接收稳定requestId及有序sources，原子创建节点并排队。调整后提交compose配方及准确sourceGroupSha256；关闭页面后后台仍处理，重启检查持久pending意图。匹配时只回写原组媒体字段，子图层、节点名称、工作区位置及尺寸保留；迟到结果不覆盖后续编辑。

绑定合成任务在后台、网页和MCP间共用一次采用效果；旧回执不会把用户撤销的结果重新激活。已取消或失败任务刷新后不自动重启，用户明确重试才开始新意图。MCP提供创建、来源读取、合成及原有采用入口，复用同一权限与版本合同。主环境完整试用、隔离实例与独立恢复通过本批检查，含原生撤销和明确声明的待回写检查点重启；证据见 `phase46-native-layers-checkpoint.json`。独立图层素材、其他图片AI和完整Agent等价继续整合。

任务成功、所有素材版本和表现资源的登记在同一完成事务内；中途失败不发布部分素材。每张输出新建 `AssetVersion`，定义中固定源资源、源SHA、朝向、配方及实际像素区域，`AssetRepresentation` 关联处理任务和输出资源。资源删除检查识别 `sourceResourceId` / `sourceStorageKey`，源图被派生版本引用时不物理删除。重复采用保持相同节点与素材身份，并保留用户已经修改的名字和位置。

本接口可脱离浏览器执行。网页Agent的本地图片工具已接入同一任务和素材体系；MCP及全部图片编辑能力的等价入口仍需继续整合。实际生产验收以整合运行目录的阶段检查点为准。

## 服务端采用结果

### 后台拆层工作流

`POST /api/canvas-projects/:id/image-layer-workflows` 接收固定原图摘要、2至8层完整计划与本次图片生成积分上限。原图复用仅限底图；区域提取绑定原图实际宽高和0至1000坐标，保留完整画布与16位透明度。模型任务复用平台目录、原生计费、积分预留和固定任务编号，不创建用户Key。模型结果仅允许不超过1%的比例舍入误差整理，不能任意拉伸裁切；尺寸一致直接复用原文件。前景只有配置并批准去背景时，才在缺少有效透明度时额外调用最多一次。

已停止的父任务可通过同一入口提交 `resumeTaskId`，保留原来的固定计划并重新确认本次积分上限。系统核对原任务、上游取消与费用状态后新建独立图层组：完成层直接复用准确资源和素材版本；已完成但尚未回写的提取或去背景结果继续使用，不重复调用该模型。未完成的步骤才创建新任务。原组、原任务和账单继续保留；删除或修改过原图层时须重新确认，不能用历史回执复活节点。任务中心的图层任务返回画布确认，不能批量重试绕过预算。

后台父任务等待子任务时释放执行名额，逐层保存固定素材版本，最终原子建立可编辑图层组与首次免费合成。页面关闭后继续执行。取消和失败先保存终态，再持续清理未完成子任务；重启后继续清理。已完成素材保留，已提交上游的费用按原生账单核对。节点改过或删除后，旧执行者不会覆盖或重新创建；同一requestId未知回复必须原样重试。

明确底图修补区域只采用选区内的新内容，选区外保持原样本与ICC。跨ICC输入在选区内转换至原图配置，支持RGB XYZ配置、sRGB与灰度；暂不能转换的自定义PNG色度/Gamma或ICC类型会明确拒绝，原图和生成素材保留。最终16位sRGB合成与保留源配置的独立图层分别有对应实际资源。输出非空但透明度不足时，保留真实结果并提示人工检查，不自动付费重试，不将任务成功作为视觉质量通过。当前积分上限包含本次图片生成及可选去背景，不包含此前单独执行的识图规划。

`POST /api/images/operations/:taskId/apply` 接收 `{requestId}`，在原画布按任务固定资源和具体素材版本新增节点、连线，返回 `taskId,canvasId,requestSha256,addedNodeIds,existingNodeIds,revision,replayed`。使用原生画布配额、历史、操作事务和回执，不再处理或上传图片。

同一操作编号重试只返回原回执；即使用户随后撤销，也不会用旧请求把节点重新加回。用户明确再次采用应提交新的编号，已有节点保持名称、位置与内容。源节点被删除或换图、结果节点被改为其他素材、资源或版本失效时拒绝写入。此入口已部署到本地影策主环境，并由原生Agent采用链路实际验证；外部自动化的完整等价范围另行验收。

新结果按完整宫格寻找原图右侧或下方较近的空位，避开已有节点；网页和上述服务端采用使用相同间距与策略。重复采用不重新摆放已存在节点，也不会覆盖用户后来调整的位置。精度、色彩、缩小操作及避让已在主环境和隔离恢复实例完成实际网页与产物核对，证据见整合运行目录 `phase22-checkpoint.json`。这些结果不等同于完整AI图片领域全部验收。

## Agent 本地图片工具

`image_process` 接收 `sourceNodeId` 和同样的 `recipe`。资源、画布及处理任务归属均由服务端确定，工具不能指定其他画布。读取源文件后，在审批中固定SHA256、朝向、像素区域与输出数量；所有写权限模式都需审批，只读模式不暴露此工具。批准前不创建处理任务、不改原图或画布；拒绝即结束当前运行并释放审批资源租约。

批准后提交一个无模型账单的原生CPU子任务。相同运行与配方重复调用复用该任务；不同运行保留独立任务归属，取消当前Agent不会借用或取消其他运行的任务。后台等待与检查点支持重启恢复。完成后通过上述采用接口固定每张输出的素材版本，写入原生画布历史和Agent变更事件；图片处理采用可撤销，素材保留。同一历史采用已被用户撤销时，重复调用不会重新添加，也不会报告已成功回写。

网格切图与按对象生成透明图层是两种工具：后者仍走 `image_layer_split` 的模型准入、审批与计费；插值缩放不声明为AI超分。两数据库专项、完整后端及前端2733项回归、生产构建已通过，最后的审批语句修订另外通过专项回归。真实Qwen在恢复实例和主环境完成审批、六图回写、226577像素核对、原图保留、深色390像素操作与重新登录恢复；见整合运行目录 `phase16-checkpoint.json`。这不代表完整图片领域或所有本地模型行为均已验证。

## Agent 对话恢复

专用拆层 `image_layer_split` 仅接受服务端解析出的 `image-tools-layer-decomposition` 协议、明确参考原图和单个多层任务；普通生图协议在提交前拒绝，不能把单张拼版声称为拆层成功。它与网页复用原任务多图资源、固定素材版本及后台CPU合成，Agent等待原生组就绪后才报告可用。合成失败和需要校正分别记录，保留模型原结果，均不自动重试模型。未配置专用模型时，可在网页确认普通参考图模型的逐层计划，外部Agent可使用同一原生接口的 `yingce_start_image_layer_workflow`；软件校准PNG验证不代表未安装模型的实测。

`GET /api/agent/history?canvasId&limit&cursor` 分页读取当前用户拥有的画布运行元数据，默认20条，最多50条；游标绑定画布，原始运行状态和其他用户记录不进入列表。`GET /api/agent/runs/:id/restore` 返回原轮次和原始用户请求，再沿用已有事件读取和SSE，不会新建模型任务。

新浏览器会找回最新原生运行；已有本机列表可在Agent的「历史对话 → 找回服务端记录」中补回。界面的「移除本机记录」只移除本地列表，服务端执行和素材保留。当前历史按不可变轮次展示，完整多轮对话归档及所有项目制作动作的自动化等价仍在整合。

本地Qwen实际试用出现过仅在聊天中要求确认、错误嵌套参数和文字声称已调用工具。工具说明已补充准确配方示例；服务端对明确的聊天执行确认最多纠正一次，未投递的纠正不会被旧快照跳过，仍未形成原生审批时明确失败，不把聊天同意当成执行批准。原始失败记录保留。
