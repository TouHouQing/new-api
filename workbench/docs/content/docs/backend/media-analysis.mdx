---
title: 素材分析与采用
description: 参考片分段、节拍和人工框选主体的本地测量、校正与时间线采用
---

剪辑工作台左侧的「素材分析」使用当前账号已保存的音视频资源。先选择片段与源区间，运行本地 CPU 分析，再核对候选。它不调用生成模型，也不需要用户创建模型 API Key。

支持参考片变化切点、音乐节拍/结构候选和人工框选主体平移跟踪。分段和节拍一次最多60秒，跟踪最多120秒；源文件最多1GiB。画面分析按实际采样时间最多8Hz，不能当作逐帧语义理解；闪光、渐变、运镜可能影响分段，节拍可能存在半速/倍速歧义。主体跟踪在遮挡或不可信时停止，不能当作人物身份识别。

任务在服务端持久执行，关闭页面不丢失。可从最近分析任务查看进度、取消或恢复；相同请求编号不会创建重复任务。原素材保持不变，结果单独保存原始测量和人工校正版本。修改名称、时间、分段、节拍或核对状态后点击「保存校正」。并发冲突会保留草稿，不能覆盖其他窗口的新版本。历史恢复另存新版本，归档仍保留来源和已采用标记；归档、恢复和丢弃草稿的确认提示固定在面板顶部。

长参考可勾选「自动保存分段检查点」，一次最多30分钟。每个55秒核心区间保留前后0.5秒上下文，只有实际测得且属于核心区间的变化切点进入汇总，不把分段接缝当成切镜。完成的区间保留固定来源、原始测量、算法版本和初始版本；失败或取消后恢复同一任务会复用已保存区间。检查点由任务管理，不出现在普通分析/归档列表，也不能手工改写。最终汇总仍需逐项核对；它不识别剧情、景别或人物身份。

参考分段核对并保存后，可选择「预览规划为分镜」，给新章节命名，检查镜头列表与原片时间，再确认新建。它创建原生章节、镜头初始版本及工作流，之后可在分镜制作中修改描述、角色和运镜。时长来自原片，不代表所选生成模型一定支持该时长。采用回执绑定具体分析版本；响应丢失或重新打开时会找回已建章节，保留后续修改。已删除章节的旧回执仍可读，原编号不会将其重建。

音乐结果可分别查看结构分段和节拍。跟踪结果会明确提示不可靠区间，每个点可定位源画面；展开「调整此点的跟踪框和构图」可人工修改主体框和构图框。修改后的手动点需要重新勾选核对才能保存，原始测量仍保留。

### 跟随构图

不需要自动跟踪时，在「跟踪画面主体」下选择构图画幅并点击「手工设置构图」。跟踪服务离线或原片缺少特征时也可使用，不创建生成任务或模型 Key。初始草稿按实际显示方向建立居中的固定画幅，起终点仍未核对。可用起终点路径，或先在原片定位后添加中间构图点；中间点可调整时间、位置或删除，起终点保留，画幅大小固定。每次修改需重新核对并保存。创建响应未知时保持参数重试会找回当前稿，不会覆盖后续修改。

原片、人工路径和采用方案预览一次只播放一个，开始播放会暂停本面板其他预览及主时间线。打开原片默认定位分析源起点。

先核对所有跟踪点；遮挡或丢失点必须人工调整，不能仅勾选通过。简单的固定/匀速路径可展开「用起点与终点修正整段构图」，输入两个位置，播放对比原画面，确认后写入校正草稿并保存。复杂运动继续逐点校正。整段保持相同裁切宽高，仅移动位置；自动简化的轨迹误差最多半个源像素，超过128个关键点时应拆分区间。

点击「预览跟随构图」检查实际源区间和片段速度，再确认采用到时间线。构图绑定具体分析版本和一个片段实例，进入原生撤销、保存和重做队列；移动、拆分和变速保持源时间映射。同一原片的其他实例、声音及字幕不受影响。监视器和MP4导出使用同一插值及偶数像素裁切；项目横竖比例与构图比例不同时补黑边。属性面板可移除当前片段构图，并可撤销。扩展片段超出已分析区间时需先移除构图或重新分析。

手机视频的90/180/270度旋转元数据按实际显示方向核对尺寸，原文件保留。旧分析若记录了编码尺寸，采用时会重新检查；不一致时要求重新分析，保留原校正历史。非直角旋转及超过64百万像素的单帧需要先转正或降低尺寸。

分段或节拍勾选核对并保存后，可预览采用到一个具体片段实例。预览列出新增和替换数量；确认后进入原生时间线命令、保存与撤销队列。标记可点击定位，其他片段可吸附到节拍。标记用源时间绑定，随片段移动、变速或分割重算，裁掉的范围会移除对应标记，撤销可恢复。采用标记不会自动剪切画面、覆盖音轨或修改同素材的其他实例。

## 旧工程分析迁入

原生转换器v5读取工程包声明的 `scenes`、`audio`、`subjects` 分析文件，将可解释的切镜、节拍/分段和跟踪结果写入同一套原生素材分析与校正历史。原片按实际字节SHA核对，时间转为源毫秒；明确的父校正关系才合并为历史，同原片的独立分析保持独立。旧根工程v4剪辑不改写，升级创建独立v5剪辑，当前工作剪辑保持原状。

原始测量与历史分析文件来源保留，人工校正另外记录。升级重用相同身份时会核对不可变来源和历史正文，不重置后来的人工作品名称、归档状态及最新校正。来源变化、父版本循环、跨类型或跨区间校正会拒绝；结构无法解释、区间或数量超过当前原生限制的分析保留为原始文件，并在转换报告中提示，不能计作完成可编辑迁移。

部分旧跟踪只保存了构图框，没有保存主体识别框。页面明确说明并仅提供构图框编辑；算法置信度仍保留，不能把构图范围当成人物识别结果。历史结果采用后依旧需要核对画面，并遵守原生标记/构图的具体版本和具体片段实例合同。旧 `reframes` 的自动转换、其他分析类型及其余制作领域继续整合。

## 本地服务

`scripts/media-analysis/worker.py` 只接收有界的规范化媒体正文，不访问任意媒体URL。使用已有 Python 环境及 `requirements.txt` 中版本的 NumPy、librosa、SoundFile、OpenCV 和现有 FFmpeg，不下载模型。

Windows 使用 `scripts/media-analysis/start.ps1`，显式传入 `-Python`、`-FFmpeg`、`-Directory`、`-TokenFile` 和可选端口。它校验目录与进程归属，复用健康的自有服务，拒绝接管其他进程；不停止 ComfyUI、Ollama 或网关。服务绑定回环地址，采用 HMAC、时限与 nonce 防止重放，串行处理 CPU 测量。仅在可信私网中转给容器使用。

Backend 配置 `CANVAS_MEDIA_ANALYSIS_BASE_URL` 与 `CANVAS_MEDIA_ANALYSIS_SECRET_FILE`，并将精确私网主机加入既有出站白名单。服务需能访问同一私有令牌；不要放进浏览器、URL或日志。任务加密固定地址、令牌、算法版本、代码及实际依赖摘要，服务发生变化时拒绝混用旧任务。旧任务恢复仍使用原配置。缓存按媒体与参数及算法摘要索引，限制64MiB和7天；失败或取消不改写原素材。

HTTP接口见 OpenAPI 的 `/media-analyses/capabilities` 与 `/projects/{projectId}/media-analyses`。MCP 0.6 提供相同的查询、运行、校正、历史、标记及构图预览/采用动作，只有启用 workspace 的连接可用。采用响应未知时先读取时间线，409须重新预览。MCP不代替用户核对；采用后仍需实际导出及检查作品。
