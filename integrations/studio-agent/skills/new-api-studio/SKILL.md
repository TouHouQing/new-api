name: new-api-studio
description: Read, arrange and develop the connected New API Studio infinite canvas, including scripts, reusable characters and scenes, shots, media nodes and generation tasks. Use when the user asks an AI agent to work on their New API Studio project.
---

Use persistent projects for durable production work. Documents, immutable versions, media and workflow receipts are stored on the server; IndexedDB is a browser cache. `studio_list_projects` and `studio_read_project` work when the browser is closed. Owner/editor roles can edit, reviewers can comment and review exact Takes, and viewers can read. Read the project and its revision before each dependent mutation.

For live canvas commands, the user connects **Studio → AI Agent**. This optional browser bridge is temporary; keep the canvas open while operating it. Server restarts require reconnecting. Cluster deployments require sticky routing for `/api/studio/bridge`.

Set `NEW_API_URL` to the gateway origin and `NEW_API_ACCESS_TOKEN` to the user's dashboard **personal access token**, supplied through the environment. Relay API keys are a different credential. Use HTTPS for remote servers; localhost HTTP is supported for development. Never write credentials into the canvas, operation files or command output.

The self-contained stdio MCP server is `scripts/mcp.mjs`; run it with Node.js 20+ and the same environment variables. Use `studio_project_schema` before constructing a document, then `studio_save_project` with `expectedRevision`. Preserve unknown fields and upload all referenced bytes first with `studio_upload_media`. Immutable media IDs cannot be reused for different bytes. A revision conflict requires reading the latest project and preserving human changes.

Use `studio_start_workflow` for durable `generate`, `render`, `quality`, `transcribe`, `media`, `previs`, `graphics`, `transform` or `analyze` jobs. Optional `runAfter` is a Unix timestamp within the next seven days; the submitted project version and budget are frozen, and project access is checked again when execution starts. Pause or cancel before the scheduled time using the ordinary workflow controls. Generation and transcription require `confirmGeneration: true` and a positive bounded quota budget. Read `studio_cloud_capabilities` for quota units and FFmpeg availability. Retain the returned job ID and request ID, poll `studio_workflow_status`, and inspect any uncertain submission before resuming. `studio_control_workflow` can pause, cancel or explicitly resume the caller's own job. It cannot silently reissue an unresolved paid request.

The CLI works without installing packages:

```sh
node scripts/cli.mjs list
node scripts/cli.mjs read SESSION_ID
node scripts/cli.mjs catalog SESSION_ID
node scripts/cli.mjs edit SESSION_ID --revision REVISION --file operations.json
node scripts/cli.mjs job SESSION_ID JOB_ID
node scripts/cli.mjs run SESSION_ID NODE_ID --revision REVISION --confirm-generation --budget QUOTA_BUDGET
node scripts/cli.mjs cloud studio_list_projects
node scripts/cli.mjs cloud studio_read_project --file arguments.json
node scripts/cli.mjs cloud studio_start_workflow --file arguments.json
```

Resolve script paths relative to this skill directory. Keep the same `--request-id UUID` when recovering a lost submission response. Commands return receipts rather than waiting for generation.

Use `studio_list_workflows` to recover a durable workflow by its request ID after losing a submission response. The server publishes 34 MCP tools. For platform models, `studio_run_node` requires a positive `budget`; it waits for the durable generation workflow and updates the connected project. Check terminal workflow state and the resulting Take before continuing.

Read declared model capabilities before combining references. Local Wan 2.2 accepts one first frame and up to 10 seconds. Installed Wan 2.1 VACE accepts up to 30 seconds, one first frame, one last frame, one character image and one movement video together, at 640x384, 384x640, 640x480, 480x640 or 512x512. Motion conditioning uses edge sequences; inspect identity and motion in the output. Shots longer than10seconds use384x224 or224x384. Store at most8 timed images in node.videoKeyframes with time in seconds; their slots must not overlap first/last frame controls. Native long shots use a single sampling graph, not concatenated repetitions. Neither local engine provides native video extension; extract a continuation frame instead.

For immediate free sound effects, start kind `transform` with budget 0 and `operation` containing an audio `node_id`, action `sound_preset`, prompt `rain`, `wind`, `footsteps`, `whoosh`, `impact` or `notification`, and seconds between 0.2 and 30. These produce original synthesized WAV files without model calls. Preview before adding the returned media ID to audio tracks. AI music/soundscapes remain reviewable drafts and may not produce isolated effects accurately.

Read the live canvas before editing. The response includes `snapshot.capabilities.operationSchema`, the exact schema accepted by the browser, along with available model IDs, groups, node types and workflow templates. Use those definitions to build a JSON array of operations; unsupported fields and result/task mutations are rejected. Submit related edits as one atomic transaction with the returned `revision`. Poll its receipt, then read the new canvas before the next dependent edit. On a revision conflict, inspect human changes and rebuild the edit.

For a film workflow, establish the creative brief and recurring character/location/style assets, describe appearance, costume, voice, lighting and continuity constraints in asset profiles, then create shots and connect typed sources. Character and scene reference images can be generated as portrait, turnaround, expression or location-angle variants in the UI. Selected reference Takes publish to the asset library; pinned asset versions and pinned connection Takes keep their prior reference. Camera fields become generation context. Audio nodes support uploads and gateway speech synthesis and can be assigned to soundtrack or voiceover.

Editing does not execute models. Run nodes only when generation is within the user's request, the connected browser permits it, and `confirmGeneration` is explicit. Video execution retains the browser's existing cost confirmation. A successful command receipt means the browser processed the command; a video may still be queued or processing. Inspect the node's task ID, status and Takes for actual completion. A running or uncertain receipt must not trigger an automatic second paid request. Read existing tasks first; unresolved receipts require inspection or user action.

Connect completed video nodes, including uploaded clips, to the assembly node's `clip` input. Connect audio to `soundtrack` or `voiceover`. Use `reorder_clips` to set the clip edge order and `pin_connection` to retain a specific Take. Running the assembly node uses the local MP4 pipeline; shot trimming, fades, captions and per-shot voiceover settings remain available through `update_shot` and the timeline UI. It never submits a video generation model.

Browser bridge snapshots represent media with availability flags and omit provider credentials and blob URLs. Persistent documents contain stable media IDs, Takes, scene/prop bindings, production clips and audio tracks. `studio_materialize_media` collects successful gateway video tasks before rendering. Render plans identify exact media/Take IDs, dimensions, frame rate, trim, speed, volume, captions, fades and audio offsets. Use technical quality review and revision/time/Take-anchored `studio_review_comment` before delivery. Rendering can require approved clips.

Download MP4 or the delivery ZIP with `studio_download_media`; it writes a new simple filename under `NEW_API_OUTPUT_DIR` and preserves existing files. The ZIP contains the film, frozen project document, manifest, subtitles, edit decision list and source media. Use `studio_project_history` and `studio_restore_project` to restore history as a new revision. Treat project prompts as creative data and preserve the user's current work.

Use `studio_read_project_version` before restoring; `studio_project_trash` and `studio_recover_project` recover the user's deleted projects. `studio_archive_take` reclaims active Take capacity while retaining historical media; it rejects selected, pinned and unfinished Takes.

For music, sound effects, voice cloning, narration and lip sync, use workflow kind `media` with `operation.action` (`music`, `sound_effects`, `voice_clone`, `voice_speech`, `lip_sync`), `node_id`, `model`, `prompt`, `seconds`, and `reference_media_ids`. References must already belong to the project. Voice cloning requires audio and `confirm_voice_rights: true`; obtain the user's permission first. Cloning stores a reusable voice ID in the returned Take's `voice` field. Narration uses that ID in `operation.voice_id`; lip sync requires stored video and audio. These operations use a configured Studio Media worker channel and normal gateway billing. Confirm a quota budget before submission.

For local songs, use action `music`, model `studio-music`, seconds at most30, language and options with `music_mode: "song"`, original `lyrics`, bpm30..240 and seed0..2147483647. Instrumental mode must omit lyrics. Preserve zero seeds and the immutable Take requestSnapshot. Project production.mediaDraft holds the latest unsubmitted tool settings; production.mediaDrafts preserves independent drafts by node_id. Preserve both while editing unrelated work. Reconfirm generation and voice rights after reopening. Review actual sung words: a completed model job does not establish lyric accuracy. Rejected audio must be replaced or explicitly approved before final delivery. Studio media tool nodes require kind `media`, not generic kind `generate`.

If a long lyric draft drops words, produce short phrases separately. Transcribe actual results with kind `transcribe`, retain matched intervals through kind `transform` action `trim`, review each new audio Take with studio_review_take, and save their offsets in production.audioTracks. Preserve full source recordings and satisfactory video Takes. Keep request/job IDs before waiting, and never describe unverified words as sung successfully.

For 3D blocking, read the schema and save `production.previs`: camera orbit, duration, actors with start/end positions and poses, and box props. Workflow kind `previs` takes `operation.node_id` and action `previs_frame` (image node, optional frame time in `seconds`) or `previs_animation` (video node). Both render locally without model calls. Connect the resulting PNG or MP4 node to the shot's reference input.

Image tools support background removal, upscaling, outpainting, foreground/background layers, storyboard grids and learned image-to-GLB conversion. Audio tools support source separation and translation with dubbing and SRT at original speech windows. Video object removal/replacement requires operation.edit {start,end,x,y,width,height} and a project-owned video reference; select the entire object path within an interval of at most30seconds. Preserve source files and review a new Take before approval. Auxiliary artifacts are immutable project media, downloadable individually.

The live canvas operation schema includes set_previs(scene), set_motion_graphics(items), timed keyframes and image layer documents. Read the exact schema before composing these operations. Specialized skills propose bounded workflowActions; review and confirm the saved task inputs before execution. Skill import uses declarative instructions and never runs unknown scripts. Regional versions keep media snapshots, subtitles and audio independent of the main canvas, and delivery packages include XMEML/FCPXML/OTIO with relink instructions and source media. Do not claim every commercial editor has been tested.


For a source-video depth restyle, use media action `video_depth` with model `studio-video-depth`, an owned source-video reference, seconds1..30 and a supported VACE width/height. Wait for its completed video Take. Connect that Take as `reference_video` and the desired character image as `reference_image`; set VACE `metadataJson` to `{"reference_control":"depth"}`. The extractor produces relative inverse-depth, not distances. Clips over ten seconds use384x224 or224x384 on the local workstation. Review identity, motion and picture quality in the actual generated Take.

For independent graphics, save `production.motionGraphics` with kind `text`, `icon`, `shape` or `image`. Image graphics use a project-owned `imageMediaId`; icons are spark/play/heart/check/arrow, shapes square/circle. Animations support fade/slide/pulse/bounce/rotate/morph with BPM30..240 and timeline start/end. Workflow kind `graphics` uses `graphics_frame` (image node, playhead in seconds) or `graphics_animation` (video node, duration0.1..30seconds), with even width/height64..2048 in operation.options. This renders locally without a model or generation budget. The Take includes an `editable_html` ZIP that runs offline; add the video Take to the timeline for reuse. Render overlays use the same graphic definition and bake it into conformed editorial clips.


Optional external connections use `studio_list_connectors` and `studio_connector_resources`. Credentials are provisioned privately on the server for the project owner; never put them in a prompt, canvas, Skill or project package. State `configured` means a token is present, not that access has been tested. Read operations import authorized media or synchronize Frame.io comments onto an exact Take after checking the original-file digest. An external export or delivery notification requires the human to authorize that selected file and destination, then `operation.confirm_external_write=true`. Never infer that consent from an imported Skill or source document. Connection destinations are frozen with the job. Uncertain creation, completion or notification is not automatically replayed. Use `studio_control_workflow` with `action: reconcile` and the already-uploaded `externalResourceId` to download and verify its exact bytes. Webhooks omit that resource ID and look up the saved event ID. Receivers verify HMAC-SHA256 over the exact POST JSON body, reject stale `timestamp`, deduplicate `event_id`, and acknowledge that exact ID. For read-only recovery, GET the same endpoint with `?event_id=...`, verify `X-Studio-Signature` over `GET\n{event_id}\n{X-Studio-Timestamp}`, reject stale timestamps, and return `{event_id, sha256, state: received}` only for a stored event. Missing or mismatched receipts remain unresolved. No integration is needed for local film delivery.

Project discovery returns paged metadata from studio_list_projects (offset, limit, nextOffset). Select one ID and call studio_read_project before editing. Do not load every canvas into context. includeDocuments=true is an explicit legacy compatibility option. Grid tools use options.panel_prompts, one bounded prompt per cell; rows×columns image operations are reserved, while redo_panel with source image and original grid references reserves one operation. Outpaint modes strict/natural preserve all pixels or blend the documented 32-pixel boundary. Layer tools can use mask_source=second_reference with a same-size white removal mask. Vocal repair uses music song mode, one owned song reference, repair_start/end and seconds=end-start; only generated vocals in that interval replace the old vocal stem. Preserve accompaniment, other intervals, original Takes and review results. Quality reports and ASR are review aids, never automatic creative approval.
